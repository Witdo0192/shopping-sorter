# Shopping Sorter

Расширение браузера для сбора просмотренных карточек товаров, поиска,
фильтрации, сортировки и сохранения товаров. Данные извлекаются со страницы
по настраиваемым CSS-селекторам. Изменение разметки магазина может потребовать
обновления селекторов.

## Установка и запуск

Сейчас сборки и сервера нет. Для использования не нужны Node.js и `npm install`.
Инструкция ниже рассчитана на Chrome; фактически проверенный браузер и результаты
запуска отмечаются в [текущем состоянии](docs/current-state.md).

1. Откройте `chrome://extensions` в адресной строке Chrome.
2. Включите «Режим разработчика» / Developer mode.
3. Нажмите «Загрузить распакованное расширение» / Load unpacked.
4. Выберите корень проекта — папку, содержащую `manifest.json`.
   В этом рабочем окружении это `E:\Projects\shopping-sorter`.
5. Закрепите Shopping Sorter через меню расширений браузера.
6. Откройте обычную страницу магазина с карточками товаров. Если она уже была
   открыта, обновите её. Нажмите значок расширения и «Открыть товары».

Открытие `popup.html` или `settings.html` как обычного файла не запускает
расширение: этим страницам нужны API браузерного расширения.
Для первой проверки выберите сайт из настроек и страницу с несколькими
видимыми карточками. Наличие домена в конфигурации не подтверждает актуальность селекторов.

## Обновление после правки файлов

1. Сохраните изменённые файлы.
2. На `chrome://extensions` нажмите кнопку перезагрузки Shopping Sorter.
3. Обновите страницу магазина, чтобы заново загрузились content scripts.
4. Закройте и снова откройте popup и страницу настроек, если они были открыты.
5. Повторите проверку затронутой функции.

Это общий порядок для любых правок. HTML popup и настроек достаточно открыть
заново, но изменения manifest, background и content scripts требуют перезагрузки
расширения; content scripts также требуют обновления страницы магазина.
Порядок установки и обновления описан в
[официальной инструкции Chrome](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world).

## Основные действия

- «Открыть товары» в popup открывает большую панель поверх страницы магазина.
- «Настройки» открывает конфигурацию сайтов, единиц измерения и производительности.
- Кнопка 🎯 запускает подбор селекторов на текущей странице.
- Переключатель в popup временно отключает обработку страницы самим расширением.
- Отдельный флажок включает счётчик найденных карточек.

## Где смотреть ошибки

- Ошибки загрузки расширения: карточка Shopping Sorter на `chrome://extensions`,
  кнопка «Ошибки» / Errors, если она появилась.
- Обработка страницы и большая панель товаров: DevTools страницы магазина → Console.
  Обращайте внимание на сообщения из `content.js` и `search.js`.
- Маленький popup: откройте его, нажмите внутри правой кнопкой → Inspect → Console.
- Настройки: DevTools вкладки настроек → Console.
- Хранение изображений и background: ссылка service worker на карточке расширения
  на `chrome://extensions` → Console.

При сообщении об ошибке сохраните её полный текст, имя файла, действия перед
ошибкой, браузер и адрес страницы. Сообщение «обновите страницу» сначала
проверьте обычным обновлением страницы после перезагрузки расширения.

## Данные и экспорт

Настройки и метаданные товаров хранятся внутри браузера, изображения — отдельно
в IndexedDB расширения. Папка проекта сама по себе не содержит пользовательские данные.

- В настройках «Экспорт» сохраняет сайты, единицы и порог виртуализации.
  Остальные предпочтения интерфейса и сохранённые товары в этот файл не входят.
- В панели сохранённых товаров «Экспорт всех» или «Экспорт выбранных» сохраняет
  товары с доступными сохранёнными изображениями. Для восстановления используется
  «Импорт» в этой же панели. Товары с уже существующим ключом не добавляются повторно.

Это два разных формата файлов. Перед изменениями хранения проверяйте восстановление
обоих экспортов в отдельном тестовом профиле браузера. Успешное скачивание JSON
ещё не подтверждает полноту резервной копии; текущие результаты — в документе состояния.

## Как вносить изменения через обычный чат с ИИ

1. Начните новый чат с желаемой функции: «Хочу, чтобы расширение умело…».
   Добавьте пример того, как это должно работать. Знать названия функций не нужно.
2. Приложите актуальную [карту кода](docs/code-map.md) и
   [архитектуру](docs/architecture.md). По ним чат определит, где нужна правка
   и какие исходники прочитать. Обычный чат сам не видит файлы на компьютере:
   передайте только те файлы, которые он запросит для задачи.
3. Обсудите решение и попросите выполнить его в существующей структуре.
   Вместе с кодом чат должен вернуть обновлённые разделы карты, если изменились
   файлы, их обязанности, зависимости или подключение.
4. Сохраните прежнюю версию в Git или копии. Примените код и обновление карты,
   выполните `npm run check`, перезагрузите расширение и страницу, проверьте
   новый сценарий. Передайте ошибки в чат; результат проверки запишите в состоянии.

Карта — навигатор для каждого нового чата. Она помогает выбрать нужные файлы
без чтения всего проекта, но не заменяет чтение кода перед правкой.
Храните её рядом с исходниками и обновляйте в той же правке: устаревшая карта
отправит следующий чат не в тот файл. Обновление карты также можно поручать ИИ.

Текст для начала нового чата:

> Хочу, чтобы расширение умело [описание и пример]. Прикладываю карту кода
> и архитектуру. Сначала определи нужные части и запроси исходники, которых
> не хватает. Соблюдай существующее разделение обязанностей; новую логику
> размещай в соответствующей части. Сохрани форматы данных и остальное поведение.
> Вместе с правкой обнови карту под фактический результат и объясни, как проверить.

## Проверки перед передачей правки

Для разработки установите Node.js 20.19+ (ветка 20), 22.13+ (ветка 22)
или 24+. После клонирования выполните из корня проекта:

```powershell
npm ci
npm run check
```

`npm ci` устанавливает версии из package-lock. `npm run check` запускает
ESLint и тесты. Отдельные команды: `npm run lint` и `npm test`.
Для обычной установки расширения эти инструменты не нужны.

Линтер обнаруживает неопределённые имена, прямое использование переменной
до объявления, повторные объявления, недостижимый код и другие включённые ошибки.
Форматирование кода не навязывается. Общие имена content scripts определяются
из объявлений файлов manifest; новые файлы по-прежнему нужно подключать в manifest.
Проверка [no-use-before-define](https://eslint.org/docs/latest/rules/no-use-before-define)
учитывает допустимые обращения к внешним переменным из callback и геттеров.
Она не проверяет момент выполнения таких callback и порядок загрузки разных файлов;
тесты и проверка в Chrome остаются необходимыми.

Если проверка не прошла, передайте в чат ошибку линтера, файл и относящийся
к ней участок кода. После исправления снова запустите `npm run check`.
